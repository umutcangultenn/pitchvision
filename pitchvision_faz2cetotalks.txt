4. Önerilen prompt sırası
Aşağıdaki sıra ile ilerlersen daha güvenli olur.

Prompt 1 — Phase 2 başlangıç / repo analizi
Current branch: milestone/phase-1-pitchvision-lite-mvp.

Create a new branch: phase-2/production-core-pipeline.

Before coding, inspect the existing monorepo structure, backend models, API routes, frontend API client, auth approach, storage/video handling, and tests.

Return:
1. Current architecture summary
2. What is already implemented
3. What is stub/mock
4. Phase 2 implementation plan
5. Files likely to change

Do not implement yet.
Bunu önce yaptır. AI projeyi anlamadan kod yazmasın.

Prompt 2 — Auth + multi-tenant
Implement real authentication and multi-tenant access control for PitchVision Lite.

Requirements:
- Remove demo behavior where missing token falls back to first user.
- Add JWT login/register.
- Add password hashing.
- Add current_user dependency.
- Add organization-scoped access.
- Add roles: Admin, Coach, Analyst, Scout, Viewer.
- Ensure every organization/team/match/player/report query is scoped by organization_id.
- Add tests proving users cannot access another organization’s data.
- Keep seed/demo login working through explicit credentials, not implicit first user fallback.
- Update README and .env.example.

Do not change video processing or YOLO in this step.
Bu en kritik güvenlik adımı.

Prompt 3 — Upload + storage
Implement real video upload and storage abstraction.

Requirements:
- Add video upload endpoint for matches.
- Validate file extension and MIME type: MP4/MOV.
- Add max file size config.
- Add local storage backend for dev.
- Add MinIO/S3-compatible storage interface but keep local as default.
- Store VideoAsset metadata in DB.
- Add signed URL abstraction.
- Extract video metadata with ffprobe/moviepy/opencv fallback:
  duration, fps, width, height, codec if available.
- Add upload status fields.
- Add backend tests for valid upload, invalid MIME, oversized file.
- Connect frontend upload page to real API when NEXT_PUBLIC_USE_MOCKS=false.
- Keep mock mode working.

Do not implement YOLO yet.
Prompt 4 — Processing job queue
Implement async processing job pipeline.

Requirements:
- Use Redis + RQ or Celery. Choose the simpler option for the current repo.
- Add MatchProcessingJob model.
- Add processing states:
  created, uploaded, queued, extracting_metadata, extracting_frames,
  waiting_calibration, detecting, tracking, calculating_metrics,
  generating_alerts, generating_clips, generating_report, completed, failed.
- POST /matches/{id}/process should enqueue a job.
- GET /matches/{id}/processing-status should return real job state.
- Add idempotency: do not create duplicate active jobs for the same match.
- Add retry endpoint.
- Add error_message and progress_percent.
- Add tests for state transitions.
- Connect frontend processing screen to real status endpoint.

CV can stay mock.
Bundan sonra Phase 2 bitmeye yaklaşır.

Prompt 5 — Phase 2 kalite kontrol
Quality check Phase 2.

Run backend tests, frontend lint/build if available, and API smoke tests.

Check:
- Auth works
- No unauthenticated fallback exists
- Organization isolation works
- Upload works
- Storage works
- Processing job starts
- Processing status updates
- Mock mode still works
- Docker Compose still works
- README is updated

Fix issues found.
Add a README section: Phase 2 Status.
Commit changes with a clear message.
Bu prompt’tan sonra branch’i pushla.

10. CV pipeline teknik mimarisi
Bence backend’de şu yapı olmalı:

backend/app/cv/
  video_io.py
  frame_extractor.py
  calibration.py
  coordinate_transform.py
  detector_base.py
  yolo_detector.py
  tracker_base.py
  bytetrack_tracker.py
  team_classifier.py
  smoothing.py
  pipeline.py
  debug_visualizer.py
Pipeline:

1. Load video
2. Extract metadata
3. Extract sampled frames
4. Load calibration
5. Run detector
6. Run tracker
7. Convert bbox bottom-center pixel → field coordinate
8. Smooth coordinates
9. Classify team
10. Save TrackPoints
11. Run analytics
12. Generate alerts
13. Generate clips
14. Generate report
Önemli: Her aşama disk/DB’ye ara çıktı yazmalı. Yoksa hata ayıklamak zorlaşır.

Örneğin:

outputs/match_123/
  frames/
  detections.parquet
  tracks.parquet
  calibrated_tracks.parquet
  metrics.json
  alerts.json
  clips/
  debug_overlay.mp4

- Keep MockDetector as fallback for tests.
- Normalize output into DetectionResult schema.
- Support classes: player, goalkeeper, referee, ball.

- Do not require real model file in CI.
Prompt 4 — Local model setup docs
Add local YOLO setup documentation.

Include:
- Python 3.11 recommendation
- installing torch/ultralytics
- where to place model files
- env variable PITCHVISION_YOLO_MODEL_PATH
- CPU vs GPU notes
- how to run detector on one sample frame
- troubleshooting CUDA/Windows/WSL2
Do not commit model weights.
Prompt 5 — Tracker
Implement tracker abstraction and initial ByteTrack-compatible tracker.

Requirements:
- TrackerBase interface
- SimpleTracker fallback for tests
- ByteTrack adapter if dependency is available
- TrackResult schema
- Track IDs across frames
- Save TrackPoint records
- Add tests using synthetic detections.
Prompt 6 — Calibration + coordinate transform integration
Integrate calibration into tracking pipeline.

Requirements:
- Use saved FieldCalibration homography matrix.
- Convert detection bbox bottom-center pixel point to field coordinate.
- Save pixel_x, pixel_y, field_x, field_y.
- Add calibration quality checks.
- If calibration missing, job state becomes waiting_calibration.
- Add tests for pixel-to-field conversion in pipeline.
Prompt 7 — Analytics from real tracks
Connect real TrackPoint data to analytics engine.

Requirements:
- Build frame snapshots from TrackPoints.
- Calculate team length, width, compactness, block gaps, defensive line error.
- Generate TacticalAlert records.
- Alerts must include confidence, severity, time range, description.
- Use non-judgmental Turkish text.
- Add tests with synthetic trackpoint data.
Prompt 8 — Debug overlay
Add debug visualization output for CV pipeline.

Requirements:
- Generate short overlay video or annotated frames.
- Draw player bbox, track_id, team color, field coordinates optionally.
- Draw defensive line and alert markers.
- Save debug artifact path.
- Make it optional via config.
Bu şekilde ilerlersen YOLO tarafı kontrollü olur.
